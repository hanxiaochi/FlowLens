# 项目交接资料包设计审查

2026-11-04，基于已发布 1.6.0。

## 当前入口核对

| 入口 | 已包含 | 缺口 |
| --- | --- | --- |
| 协作草稿下载 | 当前单据编号、修订、填写值、办理意见、待重试请求 | 常规草稿没有完整表式、办理历史和已保存附件 |
| 协作打印版 | 已保存表式、字段、办理历史、附件名称及大小 | 附件原文件需要逐个下载 |
| 单附件下载 | 当前项目权限校验、二进制、文件名及完整性检查 | 多张单据需要反复下载，缺少统一核对清单 |
| 设计端应用包 | 应用定义、项目、记录与内联附件 | 协作端导入限制 24 MiB，无法承担增长后的大型项目资料交接 |
| 数据库备份 | 全实例业务、附件、账号哈希、权限与维护记录 | 实施者按项目交接时需要范围更小的资料出口 |

以上分别核对 team-ui.js 的 draft、recordView、adminView，forms-print.mjs 的 printableForm，team-store.mjs 的 visibleWorkspace、attachment，以及 scripts/team-admin.mjs。

## 下一阶段实现约定

- 项目工作台提供明确的资料包下载入口。服务端按当前登录账号和指定项目检查权限，禁止把另一个项目的记录或全站账号带入。
- 资料包包含可直接打开的索引、逐单据打印页、结构化项目数据、独立附件、文件大小和 SHA256 清单。保留表式快照、单据关联与实际操作者历史。
- 使用生成的内部文件路径，原文件名写入清单。相同文件名、路径分隔符、恶意 HTML、Unicode 边界均需测试。
- 使用一致的工作区修订创建导出快照。导出期间的后续写入不改变已生成的资料集合，读取损坏附件时失败并给出明确结果。
- 先实测打包内存与磁盘开销，设置明确的导出边界。优先复用已有压缩依赖与表单打印逻辑。
- 新增项目资料导出后，数据库备份继续负责全实例恢复。资料包恢复需要单独实现导入预检、编号冲突与账号映射，后续作为独立目标验收。

## 验收安排

1. 两项目、重复文件名、跨表关联与附件样例，确认导出范围。
2. 撤销成员、停用账号、未登录、损坏附件及导出中断检查。
3. ZIP 解包后逐文件哈希核对，离线打开索引及表单，复验原有下载。
4. 本机与云端虚构资料演练，记录实际耗时、内存和包大小。
5. 中英文 README、升级文档和发布包同步更新。

真实业务确认与维护安排保留在交付计划 P01 至 P05。当前推进资料出口的实现和技术验收。
