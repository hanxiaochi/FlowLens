# FlowLens 1.2.0：同一份表，一直走到交付

之前导入监理表，再切到系统设计或下载接口，可能看到的是独立的员工示例。这个断点在 1.2 中补上了：选中的业务表单现在决定字段、办理路径、数据结构、接口和交付文件。原型实验室仍保留，可显式切回。

## 这次交付的内容

- 虚构整改闭环：监理指令 → 施工单位回复 → 监理复查 → 资料归档。复查可退回整改阶段，编号和历史不变。
- 文字、数字、日期、单选、是否、关联业务六类字段；配置单位、范围、原文依据及人工确认状态。
- 表单、交互说明、系统设计、开发交付共用当前模板快照。部署世界引用同一业务，解释未来设备、网络、服务与数据的关系。
- 交付 ZIP：原表定义、系统定义、OpenAPI 3.1、PostgreSQL DDL、验收案例、本地规则验证器。解压后用 Node.js 22+ 执行 `node verify.mjs`。
- IndexedDB 事务成功后才更新页面业务状态。旧标签写入会被拒绝，可下载未保存草稿，再备份并重新读取。
- v1 工作包可恢复为 v2；未声明类型的旧字段仍按文字处理，不猜测历史数据类型。修改模板不覆盖已有实例快照。

## 五分钟试用

1. 打开在线 demo。已有旧存档时，点击“体验整改闭环样例”，它只添加样例，不清空旧数据。
2. 以专业监理提交指令；切施工单位，填写整改措施、日期和证据说明。
3. 切专业监理，填写退回原因并退回整改。再切施工单位补充和重提。
4. 专业监理复查后交资料员，填写归档信息并签收。
5. 在交互实验室查看实际本地保存链路，在系统设计核对字段与流转，在开发交付下载 ZIP。

## 已执行的验收（2026-11-02）

- `npm test`：61 项通过。新增字段类型、指定退回、幂等重放、旧版本拒绝、工作包兼容、事务失败、两连接并发等检查。
- PostgreSQL DDL 在 PGlite 实际执行；数字范围约束能拒绝非法写入。
- 浏览器完整走通指令、缺必填拦截、整改回复、退回、重提、复查与归档，共 7 个业务事件。
- 浏览器两个标签同时编辑：A 保存后，B 提交被拒绝；B 输入仍保留，状态没有假装推进。
- 从浏览器下载实际交付 ZIP，在单独目录运行 `node verify.mjs`：22 条本地规则检查通过，无需安装依赖。
- 三维场景正常渲染，部署方案与节点说明引用当前整改表；旧独立原型入口保留。
- 静态构建检查模块可解析、关闭公开 AI、无服务端文件和凭据样式字符串。公开材料只包含虚构样例。

## 边界与下一关

这次完成的是可交接的业务定义与本地推演。生成的 SQL 和接口是实现起点，不会自动启动后端。JSON 工作包不是防篡改审计存证；角色下拉不是登录，布尔“已核对”也不强制为“是”。单选结论不会自动路由，办理人需选择继续或退回。

未交付：真实多人登录、项目数据隔离、生产事务服务、电子签章、对象存储、备份恢复演练、多人协同及云资源部署。没有重新录制 1.2 视频；README 中的视频仍明确标为 1.0。没有把真实监理原件上传到公开演示。
