# 团队协作部署与交付

团队协作服务把项目、成员权限和业务保存在服务器。设计工作台继续用于确认表式和规则，管理员将导出的整个应用包导入协作服务，再分配账号和项目角色。

## 本机试运行

安装 Node.js 24 LTS。协作服务使用 Node 内置模块及随包附带的 fflate，解压协作包即可运行。设计工作台仍按根目录 README 安装依赖。

PowerShell 中先读取管理员初始密码到环境变量，初始化后移除变量。密码至少 12 位，请使用自己的密码。

```powershell
$env:FLOWLENS_ADMIN_USER = 'admin'
$credential = Get-Credential -UserName admin -Message '设置 FlowLens 管理员初始密码'
$env:FLOWLENS_ADMIN_PASSWORD = $credential.GetNetworkCredential().Password
node scripts/team-admin.mjs init
Remove-Item Env:FLOWLENS_ADMIN_PASSWORD
npm run start:team
```

打开 http://127.0.0.1:4186/，登录并进入管理后台。

1. 从设计工作台导出整个应用，导入 JSON。
2. 创建成员账号，通过安全渠道交付初始密码。成员登录后可修改密码。
3. 按项目为成员勾选角色。管理员也需要项目角色才能办理业务。
4. 成员从项目待办办理。阶段切换后，服务端重新检查角色和记录修订。
5. 离职或停止试用时停用账号。停用立即撤销全部登录会话。

应用包导入为追加操作，重复模板、应用、项目或业务编号会被拒绝。更新已有应用时使用“发布已有应用的新表式”，修改过的模板需要更高版本号。服务器保留现有业务及其表式快照，新建业务使用新版本，新增项目可一同带入。先在恢复的试验实例确认新规则，再更新正式实例。导入前历史显示为“导入前记录”，服务器办理历史记录真实登录账号。

## 配置

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `FLOWLENS_DATABASE` | `.local/team.sqlite` | SQLite 文件路径，需持久化 |
| `FLOWLENS_ORIGIN` | `http://127.0.0.1:4186` | 浏览器使用的完整源地址 |
| `HOST` | `127.0.0.1` | 监听地址，容器内部使用 `0.0.0.0` |
| `PORT` | `4186` | 服务监听端口 |

外部访问配置 HTTPS 源地址，由反向代理终止 TLS 并保留原 Host。会话 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 配置时启用 Secure。服务器拒绝不匹配的 Host、跨站 Origin 和缺少同源标记的写请求。`GET /health` 可用于进程健康检查。

1.4.1 起，登录限流按实际连接来源与账号组合累计失败尝试，15 分钟最多 20 次，同一来源合计最多 100 次。成功登录释放本次额度。默认代理部署下来源为网关，因此大量失败尝试仍可能影响同一网关下的用户。限制保存在进程内存，服务重启后重新计数。

## 容器部署示例

准备一台有 Docker Compose 的 Linux 主机，域名解析到该主机，并开放 80、443。本仓库提供单实例 Compose 和 Caddy 配置，实际主机上的构建、证书签发与容量需部署后验收。

```sh
export FLOWLENS_DOMAIN=flowlens.example.com
docker compose -f compose.team.yaml build
docker compose -f compose.team.yaml run --rm -e FLOWLENS_ADMIN_USER=admin -e FLOWLENS_ADMIN_PASSWORD app node scripts/team-admin.mjs init
docker compose -f compose.team.yaml up -d
```

初始化前将 `FLOWLENS_ADMIN_PASSWORD` 通过受保护的终端或密钥管理工具注入环境，完成后清除。禁止将实际密码写入 Compose、Git 或镜像。业务数据和网关证书使用具名卷。迁移主机时同时保存业务备份和网关配置。

## 备份与恢复

备份命令通过 SQLite 在线备份 API 获取一致性快照，可在服务运行期间执行。目标文件必须尚不存在。

```sh
node scripts/team-admin.mjs backup /secure-backups/flowlens-2026-11-02.sqlite
```

备份含账号密码哈希、业务内容及附件，应存放在受限目录并按项目要求做加密和异地保管。SQLite 本身未开启静态加密，磁盘加密由部署环境提供。

恢复前停止目标服务，使用新的数据库路径。

```sh
FLOWLENS_DATABASE=/data/restored.sqlite node scripts/team-admin.mjs restore /secure-backups/flowlens-2026-11-02.sqlite
FLOWLENS_DATABASE=/data/restored.sqlite npm run start:team
```

Windows 可通过 `$env:FLOWLENS_DATABASE` 设置路径。恢复命令拒绝覆盖已有数据库，检查 SQLite 完整性及版本，并清空旧会话。重新登录后核对账号权限、业务数量、附件和至少一次完整办理，再决定是否切换正式路径。

升级前备份并保留上一版程序。发生问题时将备份恢复到新路径，使用与备份匹配的程序启动。直接复制运行中的 `.sqlite` 文件可能漏掉 WAL 数据，应使用备份命令。

管理员忘记密码时，服务器操作员可用初始化时相同的环境变量指定账号和新密码，运行 `node scripts/team-admin.mjs reset-password`。此操作撤销该账号的旧会话并记录审计。

## 管理员运行状态与交付检查

1.5 起，管理员可从顶部进入“运行状态”，查看工作区用量、数据库主文件及 WAL、账号业务数量和工具记录的备份结果。`team-admin.mjs backup` 生成快照后校验完整性、记录 SHA256。恢复操作保留业务及检查历史，并重置维护状态和登录会话。

“交付检查”分别记录实例和项目的确认事项。填写确认人和依据后保存，服务器记录实际账号和修订。填写期间配置或记录有变化时会拒绝覆盖，先下载草稿再重新读取。通过项遇到实例地址、恢复或项目配置变化时需要重新核验。未确认事项可以保存为待确认，保留待办说明。

JSON 状态报告与交付报告供维护接手使用。报告中的记录体现管理员填写的结论和工具观测，真实业务确认、异地备份及长期监控按项目安排执行。

## 当前运行边界

- 单实例、小团队试运行。工作区采用事务化 JSON 存储，业务规模扩大时需迁移到分表存储并重新测量。
- 工作区元数据上限 32 MiB，单个附件 10 MiB，每份业务附件合计 30 MiB。1.6 起附件二进制独立存于同一 SQLite 数据库。工作包结构上限沿用设计端校验。
- 项目成员可以读取该项目内业务和附件，只有当前阶段的授权角色可以修改对应字段。暂未提供项目内按记录保密。
- 同一账号获多个角色时可办理这些角色，职责分离需按项目要求分配独立账号。
- 备份恢复和审计用于追溯与运行维护，正式电子签章需另行集成。
- 生产试点前确认真实表式、办理规则、域名证书、容量、备份存放和恢复责任人。请记录真实环境的测量结果。

## 1.6 数据库升级

数据库结构由 1 升至 2，首次启动会先创建迁移前快照，再原子迁移工作区和历史请求中的附件。升级前停止旧程序并备份，预留快照及数据库整理空间。旧版程序无法打开新结构，回退需要升级前结构版本 1 的备份和新的数据库路径。完整步骤见 [1.6 升级与回退](release-1.6.0.md)。

自定义客户端发送 `X-FlowLens-Client: 2` 获取附件引用，再调用受权限控制的附件下载接口。旧内联协议在原始附件总量超过 24 MiB 时会提示刷新。设计端导入大小边界保持原有校验。

## 项目资料交接

1.7 起，从项目工作台点击“下载项目资料包”，等待下载完成后完整解压 ZIP，打开 index.html。包内包含该项目的已保存表单、办理历史、表式快照、关联信息、独立附件和文件 SHA256 清单。附件采用内部编号文件名保留常见扩展名，原名称在索引与 project.json 中对应。

当前项目成员和管理员可以导出，服务器在读取时核对账号和项目权限。单次资料内容上限 64 MiB，同一进程同时发送一份资料包。达到上限或有其他导出正在发送时会明确提示，取消下载后可以重试。导出采用一致的数据库读取快照，损坏附件会导致整份导出失败。

资料包可用于阅读、交接和恢复为独立项目。整实例恢复使用管理员数据库备份。manifest.json 列出其他文件的大小及 SHA256，清单本身需由交接双方核对。下载后的资料含该项目业务内容，请按项目交接范围保管。

## 资料包检查与恢复预检

1.8 起在管理员顶部提供“资料包检查”。选择项目 ZIP 后点击上传，服务器核对压缩结构、文件清单、附件及项目关联，并列出当前实例的编号冲突、表式差异和待确认角色。检查结果可以下载为 JSON。

ZIP 最大 66 MiB，展开内容最大 64 MiB，最多 10000 个文件。接受 FlowLens 资料格式的存储或 Deflate ZIP，拒绝分卷、加密、数据描述符和不符合路径约定的内容。解压时限制实际输出长度。检查页只呈现结构化报告，资料包中的 HTML 保持为待交接文件。

文件哈希与资料包自带的清单核对，业务真实性仍需双方确认。检查阶段生成报告，核对后可继续准备恢复到独立新项目。

## 确认后恢复项目资料

1.9 起在资料检查结果下提供“准备恢复到新项目”。填写新项目名称，勾选目标实例中的成员及办理角色，再预览新增内容、附件用量和未分配角色。核对资料来源后勾选确认并提交。

恢复会创建独立的应用、项目、表式及单据内部编号，重建单据关联和字段来源。已填写内容、业务编号文本、历史版本和办理状态按资料包保留。外部历史操作者明确标记，本次恢复操作者由目标实例记录。已有项目合并继续作为独立能力评估。

提交前重验资料包 SHA256、实例修订和目标成员状态。附件、业务、成员安排、审计与操作回执在同一事务写入，失败会回滚。请求结果丢失时，从顶部“继续待确认恢复”重选原 ZIP，可重试同一次请求。浏览器只保存已确认参数和编号映射，ZIP 需用户重新选择。清理站点存储会清除本机重试信息，操作前应先核对目标项目是否已经生成。

每次最多安排 100 个账号，每个账号最多 30 个项目角色，恢复请求参数编码后最多 64 KiB。未安排的角色可以在恢复后由管理员补充。真实人员权限按业务职责确认。

## 待确认操作的浏览器恢复

1.11 起，单据的新建、保存、提交、退回、继续办理和附件上传会先暂存原请求，再提交服务器。普通请求的客户端超时为 30 秒，附件上传、应用导入和表式发布为 120 秒。

结果待确认时，可重试原请求，也可刷新后登录原账号，从顶部“恢复待确认操作”继续。恢复列表显示项目、表式、操作和时间，可以查看摘要、下载完整原请求，并保留记录去核对服务器上的项目。勾选已核对服务器状态后，可以移除本机记录。

本机记录包含填写值、办理意见和附件数据，存放在当前浏览器的 IndexedDB。成功确认后自动清理。清理站点数据会删除恢复记录，重要内容可先下载。填写中尚未点击业务按钮的内容使用草稿下载和离开提示保护。

数据库 CLI 还原后会更换实例标记并清除会话。旧环境请求须核对当前业务后处理，页面会禁用不匹配实例的继续确认。账号和表式版本也在服务器事务内检查，已提交操作继续复用回执。

升级服务后，应保存当前填写内容并刷新网页。恢复存储失败时会保留页面输入并提示处理，管理员可先检查浏览器存储权限与剩余空间。

## 1.12 填写中的本机草稿

填写普通字段、明细行或办理意见时，页面把当前内容暂存在浏览器，并显示保存状态。草稿保存成功后可在同一浏览器的“本机填写草稿”中找回。每个编辑页面有独立草稿编号，避免多页面互相覆盖。正式业务数据由保存、提交或办理按钮写入服务器。

核对入口先重新验证登录身份，再读取有权限访问的服务器单据，展示原修订、当前修订及内容差异。账号、实例、修订和办理权限相符时，可以带回可编辑字段。原备份继续保留，新编辑保存为另一份草稿。修订或权限变化时需人工核对；旧环境草稿提供下载后人工处理。

成功提交后只清理该请求关联的草稿版本。结果未确认或本机清理失败时，使用“恢复待确认操作”继续处理原请求。其他页面的草稿不会随此次保存一起移除。

草稿包含填写内容、办理意见和用于阅读的字段定义，保存于当前浏览器的站点数据。草稿列表按当前登录账号显示。已在本机保存的内容可下载，即使之后失去项目权限；服务器读取和业务写入仍按当前权限执行。清除网站数据会移除本机草稿。共享电脑应使用各自的浏览器用户配置，并在交接前核对、下载及移除本机材料。

存储失败时页面保留输入，并提示下载当前草稿。未提交内容的离页提醒继续保留。跨浏览器与跨设备草稿同步尚未实现。

## 1.13 配置业务清单摘要

在设计工作台打开表式，点击“配置清单摘要”，按顺序选择最多三个填写区。没有选择时使用自动摘要。保存后表式版本增加，重复保存相同配置不会增加版本。移除字段会同时移除对应摘要选择，没有剩余选择时恢复自动摘要。

导出应用包，在团队管理后台导入应用或发布表式更新。当前模板及历史单据快照都经过摘要配置校验。新配置用于此后创建的单据，已有单据继续使用原快照。团队成员看到的摘要仍受项目访问权限限制。

设计工作台的业务台账、项目业务卡片和协作清单共用显示逻辑。摘要是最多三项的简短预览，完整值通过打开单据读取。


## CSV 台账迁入

1.16 起，拥有表式填报角色的成员可在项目卡片选择“从 CSV 导入”。先将台账另存为 UTF-8 CSV，核对列名和编号文本，再逐列选择填写字段或忽略。每批最多 500 行、200 列、2 MiB。预览按 50 行分页，可筛选错误及同批重复值。日期为 YYYY-MM-DD，布尔值为 true/false，明细可按字段格式提供 JSON 数组或在草稿中补填。

确认创建后生成草稿，仍需补齐必填项并按原流程提交。重复行提示供核对，保留的每行都会建单。相同原请求重试只确认一次导入，新操作编号代表另一批导入。请保留下载回执并核对已有业务。

预览后表式或项目变化时，从恢复列表下载原请求和 CSV，核对服务器业务后处理旧记录，再重新预览。备份还原后的新实例拒绝旧请求。浏览器清除网站数据会丢失尚待确认的本机请求，请先下载保存。


## 从只读介质准备恢复文件

恢复前保留原始备份。SQLite 的 WAL 模式文件在缺少旁文件、且所在位置完全只读时，即使以只读方式打开，也可能在完整性检查时报 `unable to open database file`。已在 1.19 候选版云端隔离容器中复现。

遇到此情况，将备份复制到受限的可写暂存目录，核对副本与原备份的 SHA256 一致，再使用副本执行恢复。恢复目标仍必须是不存在的新数据库路径。只为暂存副本提供当前服务账号所需的读写权限，不修改原备份或正在运行的数据库权限。恢复后核对项目、单据、账号角色和附件，并确认旧会话失效。暂存副本也含业务和账号哈希，需要按备份文件管理。

1.19.0-rc.2 开发代码已自动在目标目录建立受限暂存副本，完成校验和会话清理后才以不可覆盖方式生成目标数据库。已验证只读文件挂载及磁盘不足清理；发布的 rc.1 仍需上述手动暂存步骤。暂存需要额外磁盘空间，建议至少预留备份大小的三倍，并保留原备份。来源含非空 WAL 或事务日志时会拒绝，请用 backup 命令生成独立快照。目标文件系统须支持硬链接；不支持时失败，不降级覆盖目标。进程被强制终止或断电可能留下隐藏的 .flowlens-restore-* 暂存目录，确认无恢复进程使用后由维护人员处理。
