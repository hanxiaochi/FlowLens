# FlowLens 可交付产品推进计划

## 当前目标与验收基线

以 1.3 的多表应用为基础，交付可自托管的多人协作版本。验收场景为指令签发、施工回复、退回重提、监理复查和资料归档。完成一阶段后记录证据并继续处理下一阶段缺口。

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1.4 服务端基础 | 共享持久化、账号会话、项目成员及角色、业务命令 API | 两个独立账号协作，越权和伪造角色被拒绝，重启后数据存在 |
| 1.4 协作界面 | 登录、应用项目列表、待办、原表填写、明细、流转与历史 | 从普通用户入口完整走通三单据业务，保存冲突保留输入 |
| 1.4 部署恢复 | 自托管启动配置、健康检查、备份恢复、审计记录 | 新目录部署、备份还原、失败写入和并发回归通过 |
| 发布验收 | 双语 README、迁移说明、版本、下载包、静态体验 | 自动测试、本地浏览器、交付包和发布文件核验通过 |
| 实施试点 | 实际业务模板、人员职责、退回与例外、验收清单 | 业务方确认流程与字段，实际账号在目标环境完成试运行 |
| 成熟度深化 | 运维监控、容量边界、异常恢复、集成及交付流程 | 按试点反馈处理缺口，逐项提供测量和复验记录 |

## 本轮实现选择

协作服务采用 Node.js 24 LTS 与 SQLite 事务存储，适用于单实例自托管。浏览器通过服务端命令办理业务，角色由项目授权确定。模型与静态公开体验继续分别部署，公开演示使用虚构数据。

模板设计使用已有工作台，管理员将应用包导入协作服务。服务端保留历史快照，并验证包结构。账号采用密码哈希和服务端会话，项目授权和办理权限在服务器逐次校验。每次写入检查版本，并保留操作者和审计记录。

## 交付门槛

- 无权限账号无法读取项目、业务或附件，不能通过篡改请求切换角色。
- 重复请求、过期版本、失败事务不会重复推进或覆盖新数据。
- 多人操作可在不同登录会话中复验，退回和重提可追溯到账号。
- 备份还原到新目录后，账号、权限、业务与附件保持一致。
- 部署文档注明单实例容量和已测环境，外部主机与真实客户验收依据实际结果。
- 发布内容经过凭据和客户材料检查，公开体验的模型生成维持关闭。

真实客户试点和外部服务器验收需要用户提供部署环境及业务确认。代码、测试、自托管包和本地多会话验收先持续推进。

## Windows 内网试点进展 · 2026-11-03

用户已选定当前 Windows 电脑，计划由同一内网的多台电脑访问。已部署独立的 1.4.1 协作运行包和 Caddy 2.11.7，Caddy 下载包与官方 SHA512 清单一致。业务服务仅监听回环，HTTPS 网关绑定指定内网地址。数据库、网关私钥、随机初始账号文件与本机脚本位于受限的本地目录。

本机通过专用根证书校验 HTTPS，五个独立账号完成样例指令、签发、退回、附件补充、重提、复查及归档。在线备份恢复到新数据库后，切换实例、重启、重新登录并核对业务、项目角色和附件一致，旧会话被拒绝。已准备公开根证书客户端包、按指纹安装/移除脚本、启动/停止/备份脚本及本机操作说明。

浏览器视觉复验已完成。监理账号经 HTTPS 登录后显示正确项目角色与三份归档记录，打开复查归档单后核对归档编号、只读字段、来源修订及实际账号办理历史。已保存本机工作台与归档页面截图。浏览器自动化响应较慢，分步读取后完成上述检查。

待完成事项如下。

- 管理员执行仅允许指定本地网段及网关端口的防火墙配置。
- 另一台真实内网电脑完成证书安装、登录和角色办理。
- 安排业务确认人、实际表式及维护责任人，确认地址稳定性、持续运行方式与异地备份。

当前实例使用虚构资料，运行方式为当前用户的后台进程，Windows 重启后需手动启动。上述结果证明本机技术链路，跨机使用与真实业务验收仍待执行。
