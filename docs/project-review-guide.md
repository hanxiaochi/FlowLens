# 交付前资料核对怎么用

适用于 1.19.0-rc.1 候选版。正式云端目前仍是 1.18.0；候选版用于隔离试用，打印分页还在验收中。

## 从项目开始

登录团队账号，选择项目，点击“交付前资料核对”。系统检查服务器已保存的单据，使用每份单据当时的表式版本。尚未保存的浏览器草稿不在检查范围内。

例如一张指令单已经签发，但签发阶段应填写的内容缺失，会列为“需核对”；仍在填报的指令单缺少整改期限，会列为“待补齐”。未来阶段尚未轮到填写的空项不会直接算作当前缺项。

| 提示 | 表示什么 | 接下来怎么做 |
| --- | --- | --- |
| 待补齐 | 当前办理阶段缺少必填内容或明细 | 打开单据，由有权办理的成员补充并保存 |
| 需核对 | 已办理资料、格式、上游关系或附件存在结构异常 | 核对原始资料、办理历史和关联单据；不要为了消除提示随意改写历史 |
| 未完成校验 | 本轮没有完成附件内容校验 | 可以单独校验下载附件，或请维护人员继续核验；不能算作附件已通过 |

这些分类依据软件中已配置的结构规则，不证明内容真实、表式适用或业务已经验收。没有配置附件必传规则时，系统也不会因为没有附件而自动报错。

## 快速找到要处理的单据

问题类别可筛选三种提示；编号或业务摘要最多输入 200 字符。查找范围是单据内部编号、标题和清单显示的业务摘要，不是所有字段的全文搜索。

“我能办理的单据”按当前账号的项目角色判断。管理员如果没有分配业务角色，结果可以是空的；这不代表项目没有问题。列表显示当前办理角色，不公开项目成员的账号明细。

点击“筛选核对结果”或在搜索框按回车。筛选在分页前执行，每页最多 50 份匹配单据。每份匹配单据仍列出全部问题。打开单据后，点击“返回资料核对”会保留筛选条件和页码。

页面上方一直是全项目统计，下方单独显示匹配数量。筛选结果为空时，可点击“清除核对筛选”查看其他问题。

## 附件为什么还有未完成校验

每次生成报告最多读取校验 64 MiB 附件内容；同一份内容只校验一次。超出部分明确标记为未完成，不会当作已通过。

“单独校验并下载”通过服务器重新检查当前访问权限及该文件的内容完整性，然后交给浏览器下载。下载失败时按错误提示处理。下载成功也不会改写旧报告中的未完成标记，因为旧报告记录的是那一轮检查的结果。重复点击“重新核对”仍可能遇到相同额度，不能据此宣称全部附件已完成检查。

## 下载给同事看

“下载最新核对清单”生成下载时的最新全项目清单，不受页面筛选影响。HTML 文件可离线阅读，包含项目、生成时间、工作区及单据修订。下载后不会自动更新；业务变化后应重新生成。

文件包含业务摘要和问题信息，交接时按项目的数据管理要求保存和分享。服务器会检查下载当时的权限，但无法收回已经下载的离线文件。

整份报告过大时会提示容量限制，分页查看仍可继续。不要把下载失败或只有部分页面的截图当作完整交付清单。候选版的 HTML 已验证屏幕阅读，浏览器打印分页尚未验收。

## 试用时怎样反馈

记录候选版本、操作步骤、问题类别、期望结果和实际结果。可以使用仓库的试点反馈模板。公开反馈使用虚构或脱敏样例，不附真实账号口令、客户附件或数据库。

正式使用前还需要业务负责人确认实际表式、阶段职责和例外处理，并安排维护人员执行备份及恢复演练。软件检查不能代替这些确认。
