# 资料包检查与恢复预检

2026-11-04，基于 1.7.0 项目资料包。

## 已确认的入口缺口

现有协作导入入口只接收设计端应用 JSON，浏览器选取上限 24 MiB，服务端请求上限 32 MiB。项目资料 ZIP 包可达到 64 MiB 内容大小，文件结构与应用 JSON 不同，需要独立入口。

现有项目 ZIP 清单覆盖其他文件，清单自身不带外部签名。文件哈希能判断是否与这份清单一致，业务真实性由交接双方核对。zipSync 在服务器导出受控文件，未来读取用户提供的 ZIP 时要先检查输入边界。

## 实现顺序

1. 提供检查器及面向用户的报告。先列出 ZIP 中央目录，再按路径、条目数、压缩与展开大小限定读取，拒绝重复路径、绝对路径、上级目录、加密条目及不支持的压缩方式。
2. 逐一核对清单覆盖范围、字节数和 SHA256。报告缺失、额外和损坏文件，并核对附件引用及项目内单据关联。
3. 复用现有表式与工作区校验逻辑检查项目结构。将历史记录与当前角色权限分开呈现，导入前报告编号冲突、表式差异与账号映射需求。
4. 浏览器只展示检查结果，由用户确认后才进入恢复步骤。实现恢复时使用原子事务和幂等操作，异常时保留目标工作区。

## 回归样例

- 真实导出的三单据关联资料包及 24 MiB 合成附件。
- 文件删除、字节修改、额外条目、重复 ZIP 名称和重复清单项。
- 相对路径穿越、Windows 盘符、反斜杠、大小写歧义与控制字符。
- 中央目录与本地头不一致、伪造展开长度、压缩膨胀和截断 ZIP。
- 跨项目关联、未知表式、重复业务编号，以及历史操作者尚未分配当前账号。
- 检查失败后目标业务与附件数量保持原样。

## 待确认与继续项

Q01 的本地离线页面视觉检查继续保留。真实表式、业务负责人、维护安排和长期运行观察继续沿用交付计划，检查器及技术回归可以独立推进。

## 1.8 开发进展

管理员资料包检查入口已实现。ZIP 中央目录与本地头在解压前核对，限定 66 MiB 输入、64 MiB 展开内容和 10000 个文件；读取受控路径并拒绝重复、符号链接、加密与分卷条目。Deflate 使用有输出上限的解压。随后检查 CRC、清单覆盖、SHA256、附件引用、表式与项目关联。

报告显示项目名称、业务与附件数量、当前编号冲突、表式定义是否一致、需确认的角色和历史操作者。报告可下载。本阶段只执行检查，资料包恢复尚未开放。用户重新选择文件后清除旧检查结果。

本机 HTTP 验收覆盖成员拒绝、管理员有效包检查、损坏包拒绝后再次检查，以及目标业务未变化。浏览器已通过小型真实导出包的上传检查。云端公开接口及浏览器也已通过 25.3 MB 资料包检查，权限拒绝和目标业务一致性核对完成。Windows、Ubuntu 各通过 87 项回归，容器验收通过。
